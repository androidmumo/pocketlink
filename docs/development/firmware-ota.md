# 签名 OTA 固件升级

源码已实现，真机升级、断电回滚及内存峰值尚未验收。升级包只有 PocketLink 应用；
不能用来切换到其他游戏、更新引导程序或分区表。服务端必须包含迁移 004，配网收信仍兼容旧服务端。

## 首次迁移与分区

现有 ESP32-C3、8 MB Flash 可容纳两份各 3 MiB 的应用，不需要增加硬件。
第一次从 factory 固件迁移需要 USB 有线烧录新引导程序、分区表、应用和空白 otadata；
旧固件不会凭空获得 OTA 能力。之后应用升级才可通过 Wi-Fi 完成。

| 分区 | 地址 | 大小 |
| --- | --- | --- |
| ota_0 | 0x10000 | 0x300000 |
| otadata | 0x310000 | 0x2000 |
| cardid（保护） | 0x356000 | 0x4000 |
| pocketcfg（配置及升级状态） | 0x35a000 | 0x10000 |
| ota_1 | 0x370000 | 0x300000 |

保留原 nvs、phy_init。迁移前读取并私密备份 cardid 与 pocketcfg，核对实际分区表；
先完成构建与合并镜像校验，再使用该次构建生成的分段 flash_args。
**禁止 erase-flash，禁止把身份备份提交或加入发布包。** 本次开发没有执行刷机。
切回诊断固件也属于有线分区迁移，不是 OTA 操作。

## 构建及签名

激活 ESP-IDF 5.5.3 后，在仓库根目录执行 `./tools/validate.sh --firmware`。
`dist/firmware/pocketlink/pocketlink-ota.bin` 是应用包；`FoloToy-AI-Passport-full.bin`
是首次有线安装的合并包，不能上传到 OTA 页面。

项目公钥固定在服务端与设备源码的两个 `trust.pem` 文件中，检查要求二者一致。
当前对应私钥保存在开发机仓库外的 `~/.config/pocketlink/firmware-signing-key.pem`，
不要公开、提交或写进服务器。请私密备份；更换公钥需要可信的有线迁移，本版不提供在线密钥轮换。

本地签名（版本与序号按实际发布修改）：

```bash
source tools/env.sh
cd services/relay
go run ./cmd/fwtool \
  -key "$HOME/.config/pocketlink/firmware-signing-key.pem" \
  -image ../../dist/firmware/pocketlink/pocketlink-ota.bin \
  -version 0.4.0 -sequence 1 -out ../../dist/signed
```

生成 `manifest.json` 和 `pocketlink-ota.bin`。序号为 1–2147483647，必须大于服务器
此前接收的所有序号，也必须大于设备已确认的序号；删除版本不会释放序号。
版本只能包含 ASCII 字母、数字、点、下划线、短横线，首字符为字母或数字，最多 32 字符。
同一应用重复构建可能得到相同哈希；重复上传应使用原签名包，不要对同一二进制重新签名。

GitHub 打包：仓库 Settings → Secrets and variables → Actions → New repository secret，
名称为 `POCKETLINK_FIRMWARE_SIGNING_KEY`，值为上述私钥文件完整内容。只在 GitHub 的
Secret 输入框粘贴，不发到聊天或 Issue。本仓库已于 2026-09-17 配置该 Secret；签名流水线仍需运行验证。
然后 Actions → Signed firmware package → Run workflow，选择 main 并填写版本和递增序号。
流水线构建、检查后签名，下载 `signed-pocketlink-<run_id>` 附件。它不会自动发布至设备或部署服务器。

## 网页与设备操作

1. 管理员登录网页，在“固件升级”选择同次打包的清单和应用文件，点击“校验并保存”。
2. 服务端校验签名、目标、大小、哈希和序号，最多保存 8 个版本。上传成功尚未发布。
3. 点击对应版本“发布”。全局只有一个发布通道，当前只适用 PocketLink / AI Passport ESP32-C3。
4. 已配对联网设备空闲时首次约 30 秒检查，此后每 30 分钟检查；有未读消息时自动检查推迟。
   也可在非配网界面长按上键手动检查。
5. 设备验证签名后显示版本，长按下键确认安装，短按确定取消。提示期间暂停收信。
6. 下载写入另一个应用分区，校验 SHA256 和 ESP 镜像后切换启动分区并重启。
   保持供电，不要在升级过程中反复按键。失败时继续当前应用。
7. 新固件完成存储、界面及 Wi-Fi 初始化后确认启动；这一检查不要求互联网可用。
   在确认前崩溃或重启，由引导程序回滚；确认后的业务错误不自动回滚。

“已发布”表示设备可发现更新，不是已升级回执。本版没有设备升级进度汇总、远程强制安装、
断点续传、差分升级或自动低电量门禁。管理员应选择供电稳定的时间升级。
撤回发布停止新的下载，已经开始的下载可能继续。只能删除未发布版本。
若要回退应用功能，重新构建旧代码并使用新的递增序号；设备拒绝已确认序号以下的包。

## 安全与恢复边界

HTTPS 验证服务器证书，下载需要设备凭证，禁止重定向。ECDSA P-256 / SHA256 签名绑定
目标、版本、序号、大小和完整镜像哈希，私钥不部署到中转服务。
这是应用层验签，没有烧录 Secure Boot 或硬件防回滚 eFuse；不能抵抗物理刷写恶意固件。
序号保存在 pocketcfg，不能擦除该分区以绕过升级规则。下载失败或断电不覆盖正在运行的应用。

服务器迁移 004 把签名清单与镜像存进现有 SQLite，最大约 24 MiB 的镜像数据，
无需新 Docker 卷或公网端口；仍使用 3002 反代。1Panel 代理需要允许至少 4 MiB 上传，
上传/下载超时建议至少 180 秒。数据库备份同时包含升级包；升级前备份，旧镜像不能打开新数据库，
回滚服务器必须同时恢复匹配的旧数据库，参见[部署](../operations/deployment.md)。

## 验收清单

- 两台真机从旧分区安全迁移，身份、Wi-Fi、绑定、未读消息保持。
- A→B→A 升级，首次启动成功后序号持久化；旧序号拒绝。
- 错误签名、哈希、目标、合并包、截断包拒绝，不切换启动分区。
- 下载中断电及下载失败后重启；新固件确认前故障回滚。
- 升级后收信与回执、扫码配网正常；测量剩余堆内存和主任务栈余量。
