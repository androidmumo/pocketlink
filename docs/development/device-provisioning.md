# 设备扫码配网与文字接收

本页对应 `firmware/apps/pocketlink` 的 P3 开发版，服务端兼容已部署的 P2 文字版本，
无需升级服务器或开放新端口。源码已实现以下流程；手机兼容性、内存峰值、真机断电和双设备通信
仍须按文末清单验收，不能把编译通过当作可直接日常使用的保证。

## 使用流程

1. 在有互联网的手机上登录管理页，生成设备配对码并复制。码为 43 个字符，10 分钟过期、一次有效。
2. 首次启动设备，会显示 `PocketLink-XXXXXX` 热点的 Wi-Fi 二维码。用手机系统相机扫描，确认连接。
   手机提示“没有互联网”时选择保持连接；扫码是否可用取决于系统相机，微信扫码不作保证。
3. 设备尝试提供热点登录页自动发现。若页面未弹出，短按确定键切换到网页二维码，或手动打开
   `http://192.168.4.1`。确定键可在两个二维码之间切换，屏幕也显示热点名称和密码。
4. 在页面扫描并选择 **2.4 GHz** Wi-Fi，或手动输入隐藏网络名称；填写密码。
   网络名称为 1–32 UTF-8 字节，中文通常占 3 字节。开放网络密码留空，否则使用 8–63 字节密码。
   不支持企业 Wi-Fi、WPA1-only、WPA3-only 或 64 位十六进制 PSK。
5. 服务器默认为 `pocketlink.mcloc.cn`，端口 **443**。这是公网 HTTPS 端口；不要填写宿主机内部的 3002。
   支持域名或 IPv4 地址，不接受带路径的 URL、IPv6 和明文 HTTP。服务器必须有可验证的 TLS 证书。
6. 粘贴配对码并提交。设备连接 Wi-Fi、通过 SNTP 同步时间、验证 HTTPS 服务器、绑定并保存配置。
   过程可能短暂切换热点信道，使手机断开；重新连接后可查看状态，不要立即反复生成配对码。
7. 屏幕提示配置保存成功后，约 4 秒关闭热点与本地配置网页。手机可切回原网络。
8. 在管理页刷新设备列表，把设备加入房间，再发送文字。设备约每 5 秒检查消息。
   上下键翻页（仅多页消息显示页码，单页消息不移动）；确定键标记当前消息已读，回执成功后接收下一条。

Wi-Fi 密码不会上传中转服务，网页不把配置写入 localStorage。页面和脚本均保存在设备中，
无需公网 CDN 或手机 App。设备不读取/覆盖原 `cardid`，使用 `PL-<Wi-Fi MAC>` 作为公开 SN；
SN 不是鉴权凭证。

配网页支持 `http://192.168.4.1` 和显式默认端口 `http://192.168.4.1:80`。若旧固件在已连接热点时仍提示“请连接设备热点”，需升级包含双栈地址校验修复的固件；不是要求关闭手机 IPv6，也不要移除访问校验。

## 后续启动与重新配置

- 已配置设备自动连接保存的网络。短暂断网自动重连，不主动打开热点。
- 长按确定键进入配网，随机生成新的热点密码和网页会话令牌；配网期间暂停收信。再次长按确定退出，保留原配置并重新连接原网络。若正在执行手机提交的连接验证，退出命令在当前操作结束后处理，不会重新打开热点。
- 配网窗口为 10 分钟。超时关闭热点，原来保存的配置仍保留；可再次长按确定开始。
- 仅更换 Wi-Fi 时，服务器地址/端口不变且配对码留空，可保留现有设备凭证和未读消息。
- 更换服务器需要新配对码。显式重新配对会更换凭证，并清空属于旧绑定的本地消息。
  同一服务器上的有效 SN 必须先在管理页撤销，再重新配对。
- 配置验证失败时不覆盖已保存的配置。重启后仍尝试旧配置；首次配置失败则仍未绑定。
- 配对请求成功但响应丢失，或绑定后本地保存失败，会出现“服务器已绑定、设备未保存”的情况。
  不得假定配对码可重用：在管理页撤销该设备，生成新码后重试。
- 暂不提供自动恢复出厂设置。存储初始化或版本校验失败时停止操作，不擦除任何分区。

## 接收与回执语义

首版设备使用 HTTPS 轮询 `/api/v1/device/inbox` 和 `/api/v1/device/ack`，不使用服务端已支持的 WSS。
这样不增加新的网络组件依赖。成功请求之间间隔约 5 秒，TLS、弱网及重连会增加延迟。

设备只持久保存 **一条当前消息**；其余待投递消息保留在服务器。收到消息后先原子保存，再发送
`received`；只有用户按确定键后才保存“已读待确认”并发送 `read`。未得到成功确认就保留状态并重试。
服务器端回执重复提交幂等；断电可能导致重复请求，但不会仅因 HTTP 读取成功就伪造已读。
已读确认成功后移除本地消息；设备端暂无历史消息列表，历史仍可在管理页查看。

房间权限撤销导致回执返回 404 时，移除本地当前消息。设备离线或停留在已接收消息上时，
已经下载的内容不会被远程即时擦除。凭证失效显示重新配对提示，不能再接收新消息。
服务器列表“有效”仍只表示凭证有效，不是实时在线状态。


字体覆盖 ASCII、GB2312 的 6763 个常用汉字和所有设备界面用字；生僻字、部分繁体字及 emoji 仍可能无法显示。主机检查会阻止新增界面文案引用缺失字形。

## 存储与安全边界

| 区域 | 地址 / 大小 | 用途 |
| --- | --- | --- |
| ota_0 | `0x10000` / `0x300000` | 首个应用槽，保持 3 MB 上限 |
| otadata | `0x310000` / `0x2000` | OTA 启动选择 |
| cardid | `0x356000` / `0x4000` | 原有身份分区，禁止覆盖 |
| pocketcfg | `0x35a000` / `0x10000` | 专用 NVS 配置、当前消息及升级状态 |
| ota_1 | `0x370000` / `0x300000` | 第二个应用槽 |

配置和消息以版本化的单个 blob 提交，服务器绑定和对应消息不会跨两次独立保存。
Wi-Fi 驱动使用 RAM 存储；应用不把密码存到默认 Wi-Fi NVS。当前未开启 Flash/NVS 加密或 Secure Boot，
有物理读 Flash 能力的人可读出本地配置与文字；不得宣称凭证已加密存储。

热点为 WPA2，随机 16 位十六进制密码、最多一个手机连接。网页 POST 需要匹配本地接口、Host、Origin
及随机会话令牌，限制请求体、JSON 深度与排队数量；本地 HTTP 仅在热点配网期间运行。
热点上的 HTTP 由 WPA2 链路保护，不是 HTTPS。中转连接始终验证证书与主机名，不跟随重定向，
不提供忽略证书开关。时间同步依赖 `ntp.aliyun.com` / `pool.ntp.org`，失败时不绕过证书验证。
不要把家庭路由器 LAN 设为与设备热点相同的 `192.168.4.0/24`，以免路由冲突。

## 构建与刷机

```bash
source /path/to/esp-idf-v5.5.3/export.sh
./tools/validate.sh --static
./tools/validate.sh --firmware
```

两份固件都会构建并校验，输出分别在 `dist/firmware/board-check/` 与 `dist/firmware/pocketlink/`。
CI 同时上传独立附件与 SHA256。开发时可直接构建本应用：

```bash
cd firmware/apps/pocketlink
idf.py build
idf.py -p /dev/cu.YOUR_DEVICE flash monitor
```

刷机前确认端口、芯片为 ESP32-C3/8 MB、分区表和当前备份。首次 OTA 迁移的分段刷机写引导程序、分区表、应用和空白 otadata，
不写 `cardid` 或 `pocketcfg`。**禁止 `erase-flash`；不要向受保护分区写文件。**
整体镜像只有在其完整写入范围结束于 `0x356000` 之前才可用于已配置设备。
构建校验允许保护区为填充值，但把填充值写入 Flash 仍会擦除原有身份，所以不能据此刷入跨保护区的大镜像。
2026-09-20 已完成单台设备首次有线安装、硬复位启动及身份区回读比对。手机配网、收信和 OTA 仍需继续验收。每次刷机后必须确认设备复位并进入应用，再开始设备测试。

## 验收清单

- iPhone / Android 系统相机扫码连接，自动弹页与第二二维码/手动地址备用入口。
- 错密码、隐藏 SSID、网络不存在、时间服务不可用、无效证书、服务器不可达、配对码过期和凭证撤销。
- 长按退出配网、失败后恢复旧网络、10 分钟超时、重复进入配网、手机中途离开、重复点击、配网成功后的热点关闭。
- 更换 Wi-Fi 保留绑定；更换服务器必须重新绑定；刷新页面不泄漏密码/设备凭证。
- 两台设备加入房间、中文消息翻页、收到/已读状态、收信或回执途中断网和断电重启。
- Wi-Fi/TLS/二维码同时存在时的最低可用堆、任务栈余量、长期重连、看门狗和屏幕稳定性。

主机测试覆盖配置边界、base64url 凭证、UTF-8、JSON 深度、DNS 畸形报文、消息状态恢复，以及页面慢响应、重复提交、
错误恢复。上述真实无线、按键、显示和掉电行为仍待设备验收。

## 蓝牙配网的兼容性

ESP32-C3 支持 BLE，但本固件尚未启用蓝牙配网。安卓 Chrome 可通过 HTTPS 管理页使用 Web Bluetooth；iPhone 常用浏览器没有同等支持，因此不能把网页蓝牙作为同时覆盖两种手机的唯一入口。当前保留热点配网；统一的蓝牙体验需要另行开发支持 BLE 的 App 等客户端。参见 [Chrome Web Bluetooth](https://developer.chrome.com/docs/capabilities/bluetooth)。

将来可由已登录页面自动生成并传送一次性绑定凭证，省去手动复制配对码；不能取消后台的账号归属验证，也不能仅凭 SN 绑定。仅更换 Wi-Fi 时，现有流程已支持配对码留空，保留原绑定。
